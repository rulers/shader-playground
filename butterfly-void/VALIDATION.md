# 造形改善の検証記録

2026-11-05 / PR #34 / `feature/butterfly-void`。MVPコミット `c51e3a0` に対する修正です。

## 修正前の確認と方針

`butterflies.js` は共通の前後翅に `iShape` による縦横比変更を加えるだけで、実際には3種類の輪郭になっていませんでした。平面の翅をyawと開閉角で回すと、特定の位相で投影面積がほぼ消える問題も確認しました。

`flower-butterflies/butterfly.js` の `SPECIES` と `traceWing` にある3種類の独立したBezier輪郭を読み取り専用で再利用します。既存作品・同梱Three.jsには変更を加えず、種類別のInstancedBufferGeometryを作ります。1 draw callより造形を優先し、3 draw calls・共有material/program 1としました。

## 造形と初回の画像確認

本番と同じメッシュ・Vertex/Fragment Shaderを使う [shapes.html](../tests/butterfly-void/shapes.html) を追加しました。3種類×正面・斜め・真横90°×カラー・白影の18セルです。固定姿勢を別の簡易モデルで代用していません。

- アゲハ型：幅広い前翅、後翅の切れ込み・尾状突起、暗い縁・筋、明るい斑紋と青い眼状紋を確認。
- アオスジアゲハ型：細長く尖った前翅、小さい尾のない後翅、暗い地に太い青緑帯を確認。
- モンシロチョウ型：小型で丸い前後翅、乳白色、前翅先端の黒斑と2つの黒点を確認。
- 白影では模様と明暗を除去し、3種類の輪郭の違いで識別できることを確認。
- 翅の曲率・自然な上反角、前後翅の奥行き差と位相差、立体の胴体・頭・触角により、真横でも側面の形が残ることを確認。カメラ正面へ向け直す補正は使いません。

開いた位相と閉じた位相のPNGを実際に開いて確認してから基準画像を登録し、通常モードの画像比較を再実行しました。正面で閉じた翅が狭くなる自然な変化は残していますが、単独の線や破綻した三角形にはなりません。

| 種類 | 真横・開いた位相の幅×高さ | 白い領域の画素数 |
| --- | --- | --- |
| アゲハ型 | 48×217 px | 5,069 |

白影を各個体のbounding boxから128×128へ正規化しても、種類間のIoUは全3姿勢で **0.479〜0.680**。単なるサイズ違いなら1に近づく比較です。色や大きさを除いても輪郭が異なります。判定の上限は0.92です。

4つの羽ばたき位相、9段階の連続yawも実際のWebGLで確認。各セルの白い領域の95%以上が同じ連結成分に属することも確認し、羽ばたき中に翅が胴体から離れる破綻を検出します。各セルの画素比較、種類別の縁取り・青緑帯・白地と黒点の画素条件を検証します。蝶1匹を消した負例は失敗することを確認。生データは [shapes-results.json](../tests/butterfly-void/captures/shapes-results.json)。

- 本番入口で自動再生、モーション低減で静止開始と明示的な再生を確認。
- 停止・再生・リセット・手動色指定、15/30秒切り替え、スライダー・Space・Esc・フォーカスを確認。リセット後に位置と描画画素のハッシュが初期状態と一致。
- 実際のマウスとCDPタッチ操作で近くの個体に風が入ることを確認。
- 非表示停止は `document.hidden` とvisibilitychangeをテスト内で注入する方式。実OSのタブ切り替えではありません。低fpsでも待ち時間の固定値で誤判定しないよう、再開後の時刻更新を待って確認します。
- 240描画後もgeometry 3・texture 0を維持。コンテキスト喪失・復帰後も同じ画面へリセットでき、最終破棄後までWebGLの警告なし。
- WebGL非対応の負例で案内表示、縦横リサイズ、外部素材通信がないことを確認。

黒の割合はRGB最大値20以下を黒とし、UIを含まない実際の描画バッファを計数。fpsは約1.8秒のrAF測定で、機材負荷によって変動します。JSヒープは1点の採取値で、GPUメモリのバイト数や長時間のJSリークを証明するものではありません。生データは [results.json](../tests/butterfly-void/captures/results.json)。

## 変更範囲と例外の理由

- UI、15秒の白影切り替え、30秒サイクル、ギャラリー構成、既存作品は変更しません。ギャラリー用の作品内 `preview.jpg` だけは現在の造形を再撮影しました。
- 遠景の点状化を減らすため正面換算で約16pxの高さを下限とし、初期配置ではその外形に合わせて間隔を確保。縦画面は144から120匹へ減らし、文字付近の通常飛行目標を上側へ選び直します。速度追従・姿勢追従・風の物理計算は維持します。
- 入力処理だけは例外的に変更。ソフトウェアGPU負荷で移動イベントの間隔が200ms以上となり、既存のガードがドラッグをすべて無視する問題を実際のイベント時刻で確認しました。ガードを1.25秒にし、実際の経過時間から入力速度を求めます。風の距離減衰・力・速度制限・減衰定数は変更していません。
- 種類別の3インスタンス描画に分け、フレーム内で新しいMesh・materialを生成しません。検証ページの描画用Canvasも再利用します。追加のnpm依存・外部ライブラリはありません。

## マージ前の未確認事項

**60fpsは未達です。** 造形を優先して立体の胴体・輪郭リング・3種類の形状を追加したため、MVPより三角形数とソフトウェアGPUの負荷が増えています。ソフトウェアGPUのfpsを実機GPUの性能とは見なしませんが、この測定を滑らかな操作感の達成とも解釈しません。

ハードウェアGPUとスマートフォン実機でのfps・風の感触・温度・長時間のメモリ、Safari／Firefox／他OSは未確認。マージ前に、実機での形状・遠景の読みやすさ・操作感・性能を確認してください。実タブ切り替えとbfcache往復も実OSでは未検証です。
