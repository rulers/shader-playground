# 作品を開発する

1. リポジトリルートの`AGENTS.md`を読み、対象のREADME・NOTICE・現在のコードを確認する。仕様の探索は`docs/ai/README.md`を使う。設計判断が必要な場合だけ関連OKFを参照し、記述の出典・来歴を一次記録と照合する。
2. 一文のコンセプト、主操作、期待する見た目・感情、最小構成、受け入れ条件を整理する。参考映像の素材そのものと、表現上の参考を区別する。
3. 既存の描画方式で目的を満たせるか評価する。GLSLの明示指定、奥行き、個体数等の必要性に基づき方式を選ぶ。新しい依存の費用を説明する。
4. `docs/ai/architecture.md`で変更元と生成物を確認する。DOM入力、状態更新、描画を対象作品の規模に合わせて分離する。変更していない作品まで抽象化しない。
5. 主操作と見た目が試せる最小単位を実装する。UIは既存の小さな＋・キャプションとの関係を確認する。停止・リセット・非表示・モーション低減の意味を定める。
6. `docs/ai/validation.md`で既存テストを選び、`.agents/skills/verify-shader-artwork/SKILL.md`に従い検証する。生成元を変更したら再生成し、差分を確認する。
7. 新作は`index.html`のカード・作品数・プレビュー・ルートREADMEと作品READMEを整える。プレビューは実装から生成する。参考動画のフレームを無断同梱しない。
8. 判断が次の制作にも役立ち、採用理由や根拠を追跡できる場合だけ`docs/knowledge/template.md`からOKFを作る。既存記録の更新で足りるか先に確認する。コードからの後付け解釈は仮説と明記し、出典のない設計意図・承認履歴を補完しない。

## 返すもの

変更箇所、操作して確認できるURL、検証結果、未確認の端末・性能・触感を示す。PR作成と公開完了を区別する。ブラウザーを起動できない場合は実描画を確認済みと書かない。
