# 既存作品を再構築用プロンプトとして書き出す

## 目的・入力

指定された作品の現在の実装を、別のAIコーディングツールへ引き渡せる形に整理する。**作品自体の変更、設計意図の推測による補完、OKFの自動作成はしない**。

- 必須：対象作品ディレクトリ（例：`conure-flight/`）。
- 任意：`mode=package`（既定。プロンプトと必要ファイルをまとめる）または`mode=inline`（テキストのみ）。
- 任意：対象AI。指定がなければ特定ツールに依存しない指示にする。
- 保存先とGitへの反映は依頼に合わせ、未依頼の公開・マージは行わない。

## 調査手順

1. `AGENTS.md`と`docs/ai/README.md`を読み、対象作品のREADME、NOTICE、HTML・CSS・JS・GLSL・生成元を確認する。無関係な全作品は読まない。
2. `docs/ai/architecture.md`を参照してエントリーポイント、生成元・生成物、同梱ライブラリ、相対パス、実行条件を特定する。必要な外部素材について出典・利用条件・取得手段を確認する。
3. コードと作品READMEから、画面構成、初期値、時間経過、操作、モーション低減、リサイズ、失敗時挙動を抽出する。「コードで確認した事実」と「期待する演出の説明」を区別する。
4. **忠実な再構築ではOKF参照を必須としない。** 設計変更・別技術への移植・不明な制約の判断が必要なときに限り、`docs/knowledge/README.md`の索引から関連するOKFだけ読む。記述の根拠をコード・PR・Issue等の一次記録と照合し、後付けAI推論を確定要件へ昇格させない。
5. ソース間に不一致があれば、矛盾・出典・不明点を明示する。資料が複数あっても同一推論から派生したものは独立証拠と数えない。

## 出力する内容

### `rebuild-prompt.md`

1. Project Overview：作品の目的と再構築の範囲。
2. Expected Experience：見た目と主操作（観測事実と演出上の期待を区別）。
3. Technology / Runtime：描画方式、依存関係、静的HTTP等の条件。
4. File Structure / Assets：必要ファイル、素材配置、生成手順、ライセンス。
5. Implementation Steps：ファイル配置、起動、必要な生成処理。
6. Source Code：`inline`なら必要なテキストの内容、`package`なら同梱ファイルへのパスと用途。
7. Interactions / Parameters：入力、初期値、時間と状態遷移。
8. Acceptance Criteria：実装と操作から確認できる検証可能な基準。
9. Evidence / References：参照したコード・README・必要時のOKFと一次記録。
10. Known Limitations：未検証環境、素材の欠落、推測、利用権限の不明点。

### `assets-manifest.md`

素材ごとに原本パス、出力先、用途、出典、ライセンス確認状況、取得方法を記す。取得や再配布を許可されていない素材は勝手に同梱しない。必要な素材が取得できない場合は再現不能な部分を明示する。

### `package`モードのファイル

必要な`source/`、再配布可能な素材・依存ファイルだけを含める。既存の`AGENTS.md`やOKF全文を無条件にコピーしない。共通ルールを別の指示として埋め込むより、作品の再現に必要な具体的な制約を出力する。

## 検証と完了条件

- リストに挙げたローカルパス・import先・エントリーポイントを実ファイルと突き合わせ、素材の欠落を明示する。
- `docs/ai/validation.md`から適切な検証を選ぶ。可能なら生成パッケージを別ディレクトリで起動して確認する。
- リンクとファイル構成の確認を、実ブラウザーの描画成功・操作感・性能検証と混同しない。実行できなかったテストは未実施と記す。
- 出力は再構築用プロンプトと関連ファイルまで。既存作品の変更、OKFの新規生成、`main`へのマージは行わない。

## 判断の基準

Code First / Evidence First / OKF Optional。検証できない設計意図は「不明」とする。厳密な移植が不要で、既存のREADMEとソースを渡すだけで目的を満たすなら、プロンプトを過剰に長文化しない。
