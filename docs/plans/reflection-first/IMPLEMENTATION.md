# #32 REFLECTION FIRST — 実装着手仕様

作成日：2026-10-30（JST）
ブランチ：`feature/reflection-first`


## 体験と画面の決定

青灰色の静かな空間、アルミの立方体一つ、鏡面の床。低い視点で上の実体と下の像を同時に見せる。鏡像を引くと、像が先に動き、実体が追いかける。実体側はつかめない。遅延のある普通の鏡に見えたら不合格。

- 背景 #151e2a、床 #334558、金属 #c6d0d9、操作可能な反射の縁 #bce9ff。タイトルは左上、操作説明は左下、作品は中央〜右。狭い画面は作品を中央、テキストを上下の余白へ。
- カメラはPerspective、FOV38°、位置(4,3.2,6)、注視(0,0.25,0)。床y=0、立方体サイズ1、初期中心(0,1,0)。影と側面の明暗を見せる。床越しの像は暗く薄い。霧・粒子・外部HDRは不要。
- 構成図：[初期→操作中→解放後](storyboard.svg)。これは概念構図でありカメラ投影そのものではない。
- 見せ場：床の像を横に引いた瞬間、実体との対応が一時的にずれ、解放後に実体が新しい位置へ落ち着く。

## 初期実装範囲と入力

一つの反射を平面内でドラッグする。持ち上げ・回転・複数立体は後続へ送る（最初の版で「反射を持ち上げられる」と説明しない）。
通常時、反射だけに細い縁を付け、hover/選択時に明るくする。上の立方体をクリックしたら短いHTMLヒント「床に映った像をドラッグ」を出す。カメラのOrbit操作は入れない。

入力の拘束平面はy=-1。Raycasterで反射メッシュをヒット判定した後、rayとこの平面の交点を使い、初回hitとのオフセットを維持して反射ターゲットのx/zを更新する。x,zを[-1.6,1.6]へclamp。画面上方向のドラッグは床の奥方向で、実体の高さ変更ではない。

キーボードはcanvasにtabindex=0。Enterで反射を選択、矢印でx/zを0.1ずつ変更、Escapeで選択解除。SpaceでPause（input/buttonにフォーカス中は奪わない）。

## 状態・更新・描画

model.mjsはcreateState/update/setTarget/resetをexport。状態はtarget:{x,z}, body:{x,z}, velocity:{x,z}, paused。初期は全座標0。入力先targetは鏡像側の主状態であり、bodyから逆算しない。

固定dt=1/120、フレーム差上限1/30、各フレーム最大4step。各軸に a=90*(target-body)-18*velocity、半陰的Eulerで速度→位置。入力がなく速度と誤差が1e-3未満ならtargetへsnapしRAF停止。反射はtargetへ即時追従し、bodyだけが遅れて追う。追従係数の初期値は要触感調整。

renderer.jsはmount/render/hitTest/resize/disposeを担当。立方体はMeshStandardMaterial、metalness .85/roughness .28。外部環境マップなしで面が読めるよう大きいKey/Fillと弱いHemisphereLightを置く。真っ黒になるなら反射表現追加より先に照明を調整。

床は鏡面風の着色平面。下に同形の反射用メッシュを別配置し、中心(target.x,-1,target.z)、上下反転。半透明・暗め、床側のdepthWriteを切り、反射→床の合成順と実体の深度が破綻しないよう設定。物理的な汎用鏡やSSRではなく、一つの像を独立描画する設計。完全な鏡面反射と称さない。実体の影は床へ落とす。追従が落ち着けば通常の対応へ戻る。

調整UI：追従の重さ（k=50..140、初期90、減衰は2*sqrt(k)*.95）、Pause、Reset。他の操作は足さない。

## 固有の受け入れ条件

- 初期画面で実体と床の像が同一物と読める。反射だけが選択可能。
- ドラッグ直後のフレームでtargetは変わりbodyは旧位置を保ち、以降bodyが追う。テストで主従を検証。
- 解放後2秒以内を目安に誤差0.01以内、暴走・永久振動なし。長時間10000stepも有限。
- 操作中/解放後の比較で単なる上下同時移動に見えない。説明なしの初見観察で「反射を動かしたら実体が追った」と読めるか確認し、読めなければ質感追加より入力の示し方を修正。
- 直接URL：/reflection-first/。実装後の追加先は同名ディレクトリ、トップのカードは最終段階。

## リポジトリ調査と共通方針

- 確認対象：ルートREADME/index.html、rainのHTML/CSS、koi/app.js、soseki/lib/three-renderer.js、noodle-discoのREADME/HTML、third_party/three/NOTICE.md。
- 当該mainの全ツリーにAGENTS.md、SKILL.md、ルートpackage.json、GitHub Actions定義は存在しない。新しい全体ルールは追加しない。
- GitHub Pagesはmainのルートを静的配信。作品ごとのディレクトリにHTML/CSS/ES Modulesを配置し、ビルド工程・CDN・追加npm依存は不要とする。
- 描画は同梱済み `../third_party/three/three.module.js`（NOTICE記載0.186.1）を使う。CPUの入力・状態更新とGPUの描画を分離する。既存PortraitRendererや麺のエンジンは用途が異なるため流用しない。
- 画面の外枠はnoodle-discoの小さい正方形＋、rain/koiの開閉・Escape・フォーカス復帰を参照する。CC BY-NC-SAのrain実装をコピーせず独自実装し、独自部分はルートMIT、three.jsの既存MIT表記を維持する。
- 作品タイトル・トップへの戻りリンク・短い操作説明をHTMLで配置。右上32pxの四角い＋、パネル初期非表示、幅280px以下・モバイルは画面幅内。×/Escapeで閉じ、トリガーへフォーカスを戻す。aria-expanded/aria-controlsを同期する。
- UI操作はキャンバスのドラッグに伝播させない。作品上のみtouch-action:none。ポインターIDは一つだけ保持し、capture/releaseを使う。pointercancel/lostpointercapture/blur/タブ非表示で必ず操作を解除する。
- Pauseは運動を停止し描画を保つ。停止中は作品操作を受け付けず、調整とResetによる一回描画は可。Resetは配置・履歴・調整値を初期化し、Pauseの選択は維持。
- reduced-motion時は自律演出を止める。明示ドラッグ中は直接追従、離した後は長い揺れを省き静止させる。非表示タブでRAF停止、復帰時に経過時間を飛ばさない。
- DPR上限1.5、描画バッファは長辺1920px以下。CSS寸法と描画寸法を分け、入力はcanvas.getBoundingClientRectからNDCへ変換。resize時は入力解除しカメラと描画サイズを更新。
- WebGL初期化失敗/コンテキスト喪失時は操作を無効化し、HTMLの説明・戻りリンク・再読み込み案内を残す。初期化はtry/catch、disposeでRAF・イベント・GPU資源を解放する。

## 共通の検証手順（実装後に実行）

1. リポジトリルートで `python3 -m http.server 8000`。file://ではなくHTTPで、下記の作品URLへ直接アクセス。
2. `node --test <作品ディレクトリ>/tests/*.test.mjs`。標準node:testのみ。長時間更新で全数値が有限、dt分割の差、Reset、Pause、キャンセルを検証する。
3. Chromiumと実機Safari/Androidでポインター/タッチ、390×844・844×390・1440×900、DPR1/2、パネル開閉・キー操作・画面回転を確認。実行環境がなければ未確認と明記。
4. 非表示→復帰、reduced-motion、WebGL失敗/喪失、連続Resetで入力の固着・多重RAF・例外がないこと。
5. 60秒の操作を計測。目標はデスクトップ60fps/モバイル30fps。端末・ブラウザー・解像度・測定結果をREADMEへ残す。未達時はDPR/影解像度を下げ、核の操作は削らない。
6. 初期・操作中・操作後の3枚を保存し、本書の見せ場と照合。合格してから実レンダリングの `preview.jpg` を取得（構成図を実装プレビューとして使わない）。
